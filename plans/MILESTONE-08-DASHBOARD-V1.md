# Milestone 8 — Dashboard V1 Execution Plan

`PLANS.md` remains the immutable governing roadmap. This file defines the concrete delivery and
acceptance contract for its Dashboard V1 milestone.

Status: implemented and verified on 2026-08-15. Automated, production-build, container, and live
HTTP acceptance passed. Interactive visual browser inspection remains pending because no in-app or
connected browser was available in the verification session.

## Verification result

- All seven planned routes were generated by the production Next.js build and returned HTTP 200
  from the containerized dashboard on an overrideable host port.
- A live contract request created a durable task, which transitioned from queued to success with a
  structured plan and execution evidence.
- The bounded activity endpoint exposed the task lifecycle from the running process, while task and
  memory queries remained database-backed.
- PostgreSQL and Redis were ready; the rebuilt API and dashboard containers started successfully.
- Automated tests cover event bounds, recent-memory bounds, lifecycle controls, capability grouping,
  and the existing end-to-end runtime suite.
- Browser-plugin discovery returned no available browser, so no screenshot or interactive visual
  claim is made.

## Objective

Turn the existing single command screen into an owner command center backed by authoritative REST
state and near-real-time WebSocket refresh. The dashboard must expose only behavior that exists and
must label later-milestone capabilities honestly.

## Acceptance criteria

- Shared responsive navigation exposes Chat, Tasks, Activity, Agents, Memory, Integrations, and
  Settings.
- Chat submits durable CEO tasks and clearly separates acceptance, execution, and completion.
- Tasks display objective, lifecycle, plan steps, evidence, errors, timestamps, and only valid
  pause/resume/cancel controls.
- Activity loads a bounded process-local snapshot, refreshes on WebSocket events, and states that
  history is not yet restart-persistent.
- Memory lists recent active records and supports bounded semantic search with provenance and
  confidence visibility.
- Agents truthfully exposes only the CEO runtime and identifies multi-agent behavior as Phase 9.
- Integrations distinguishes built-in capabilities from external integrations and identifies MCP
  installation as Phase 10.
- Settings shows API readiness and computer, browser, vision, and voice status without exposing
  secrets or adding unsafe mutation controls.
- Loading, empty, offline, and request-error states are visible and non-deceptive.
- REST remains authoritative after WebSocket connection/reconnection.
- Backend tests, Python lint/type checks, dashboard tests/type checks, production build, Compose
  validation, and a live container smoke test pass.

## Architecture decision

No new dependency or framework is introduced. A bounded in-process event snapshot complements the
existing live event hub until Redis distribution and durable audit history are implemented. A
read-only recent-memory query reuses the existing persistent memory service.
